## Findings

### Blocking

- None for the newly added non-replacing outer solve/filter stages behind the baker. They are diagnostic-only and must not be mistaken for replacement readiness while production replacement coverage remains incomplete.
- Async readback remains blocked for production. The recorded `buffer_get_data_async()` callback did not arrive within 180 frames, so the first compute implementation must not choose async readback unless a later probe proves it.

### Important

- Legacy baseline is closed for this slice. `R7_LEGACY_BASELINE_OK` proves nonzero/non-full collision coverage, no support fallback, occupied water/obstacle metrics, exact top-level pass counts, `flow pressure jacobi pass=40`, diagnostics/postprocess, and RiverManager result handoff.
- The non-replacing compute backend skeleton is closed for this slice. `R7_COMPUTE_BACKEND_SKELETON_OK` proves baker-owned local RenderingDevice setup, RGBA16F/RGBA32F format preflight, delayed single-submit/wait/sync/storage-buffer readback, no async readback, no same-list read-after-write dependency, and idempotent cleanup/abort calls without changing RiverManager texture state.
- The first isolated solve/filter compute step is closed for this slice. `R7_COMPUTE_SOLVE_FILTER_STEP_OK` proves a baker-owned RGBA32F pressure-Jacobi compute dispatch behind the non-replacing backend, deterministic legacy-UV CPU-reference correctness, delayed single-submit/wait/sync/`texture_get_data()` readback, local RD cleanup, and unchanged legacy RiverManager texture IDs/hashes. The refreshed proof also runs the same synthetic pressure/divergence/occupancy intermediate through `flow_pressure_jacobi_pass.gdshader`, covering source-size stride, atlas-column cross walls, the legacy 2% padding wall, solid-cell behavior, y clamp, and pressure/divergence encoding.
- The production-shaped pressure-Jacobi stack proof is closed for this slice. `R7_COMPUTE_SOLVE_FILTER_STACK_OK` proves baker-owned RGBA32F ping-pong pressure textures, the real low-cost fixture schedule `[32, 16, 8, 4, 2, 1, 1, 1]` with 5 iterations per stride, 40 dispatches in one compute list, 39 `compute_list_add_barrier()` calls, delayed single-submit/wait/sync/`texture_get_data()` readback, a legacy shader multi-pass intermediate comparison, and unchanged legacy RiverManager texture IDs/hashes. The pressure stack uses `R7_PRESSURE_JACOBI_STACK_INTERMEDIATE_V1` for accumulated f32 compute versus legacy f16 shader feedback; final generated textures still require `R7_TOLERANCE_V1`.
- The expanded projection-pass diagnostic is closed for outer-pass correctness. It adds divergence, gradient subtract, and two boundary tangency compute passes around the stack, records 44 dispatches and 43 dependent-dispatch barriers, keeps output texture keys empty, and leaves RiverManager texture hashes unchanged. With captured legacy pressure, projection parity and generated `flow_foam_noise` parity pass `R7_TOLERANCE_V1` after the same final combine/postprocess path.
- The controlled legacy pass-6 sampler diagnostic is closed for instrumentation. It runs the real `FilterRenderer.apply_flow_pressure_jacobi` canvas shader at `stride=16`, `source_size=64`, `texture=106x106`, and `atlas_columns=5` with uniquely encoded neighbor texels. Horizontal stride-16 reads are atlas-wall center reads for all probe points, but vertical `26.5`-texel reads split lower/upper choices by probe position (`3/2` for both up and down), so one global floor/ceil/tie or bias rule is not a valid parity model.
- The legacy pressure-feedback correctness audit is closed for this slice. The pressure/divergence/project/tangency shaders implement a coherent intended solve, including atlas-wall, Y clamp, solid-cell, and pressure/divergence encoding behavior. The mixed pass-6 vertical sampling is therefore a canvas renderer artifact rather than shader intent. A new 25-point grid diagnostic supports that interpretation while rejecting a simple production rule: the `upper when point.x < point.y, otherwise lower` model matches `22/25` up and `22/25` down samples, but it misses `(10, 63)`, `(31, 63)`, and `(53, 63)`. No visual artifact evidence currently proves either that legacy output is visibly wrong or that compute output is objectively better.
- The opt-in canvas-tie diagnostic is useful but not accepted for replacement. `pressure_jacobi_canvas_tie_mode=1` lowers generated p95 angle from `3.48932145236808 deg` to `3.02500924801543 deg` and weighted mean from `0.76174545540638 deg` to `0.60170081393187 deg`, but worsens p99/max angle from `5.48129340327964/12.4395520353247 deg` to `5.96108559105589/18.2393832633789 deg`. Occupied R/G p99 failures remain, so the diagonal tie bias stays diagnostic only.
- The source-edge sampler model is useful but not accepted for replacement. Dense scanline/y-band diagnostics show the controlled pass-6 sampler tables are exactly fit by `upper when point.x < point.y except source_size - 1 row, otherwise lower` (`25/25` grid, `95/95` scanline, `209/209` y-band for both up and down). The opt-in `pressure_jacobi_canvas_tie_mode=2` candidate remains non-replacing and diagnostic-only: p95/weighted mean improve to `2.81378265972502 deg`/`0.51408882340789 deg`, but p99 remains worse than primary at `5.71058370749061 deg`, max remains `18.2393832633789 deg`, angle-over-10 count rises to `7`, and occupied R/G p99 still fail.
- The pass-limited pressure prefix diagnostic explains why the controlled source-edge sampler model is insufficient. Pass 5 is clean for all modes, but primary mode 0 first fails at pass 6, stride 16 iteration 1 (`occupied_r_p99_abs=0.18359375`, `occupied_r_max_abs=0.234375`) and peaks at pass 10 (`occupied_r_p99_abs=0.30126953125`). Modes 1/2 suppress broad stride-16 p99 drift but still have local max errors from pass 6, fail p99 by pass 8, and peak p99 at pass 15. The primary max-angle target `(82, 47)` gets a pressure delta `2.140625` at pass 15; modes 1/2 fix that target but create the `(61, 67)` tail with pressure delta `0.3671875` at pass 20 and generated max angle `18.2393832633789 deg`. Mode 2 also moves occupied G/R failure clusters into tile 5 `(42, 63)`, so it is over-applied for generated-output replacement even though it fits the controlled sampler.
- The probe-only `FRAGCOORD` diagnostic supports the UV-artifact hypothesis. Legacy UV y-band rows had 20 total X-dependent transitions, while the `FRAGCOORD` variant had 0. This means the remaining target should be canonical texel-space compute behavior rather than exact CanvasItem interpolated-UV artifacts. The diagnostic does not promote the compute floor model, diagonal model, or source-edge model because the `FRAGCOORD` variant did not select the canonical compute model uniformly.
- The primary compute-pressure generated candidate is not ready for replacement. The latest pressure-feedback retry improved generated p95/max angle from `3.60344260089818/16.9067074883773 deg` to `3.48932145236808/12.4395520353247 deg`, but it remains report-only and fails `R7_TOLERANCE_V1` with occupied G p99 `0.00784313678741` and occupied R p99 `0.00392159819603`.
- The `R7_TOLERANCE_V1` gate audit keeps the final replacement gate unchanged. The decoded-flow mask `expected_magnitude >= 0.05` remains valid for replacement risk, but the probe now reports diagnostic-only p99 angle, weighted mean angle, endpoint delta, magnitude buckets, tile-edge buckets, and max-angle records. Current failures are not only low-magnitude or padding noise: generated p99 angle is `5.48129340327964 deg`, weighted mean angle is `0.76174545540638 deg`, strong-magnitude (`>= 0.20`) p95 angle is `2.12881948668782 deg`, tile-inner 1px p95 angle is `3.54360459424017 deg`, and occupied G p99 still fails at `0.00784313678741`.
